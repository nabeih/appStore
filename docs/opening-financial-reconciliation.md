# تسوية التغييرات على المخزون الافتتاحي المثبت ماليًا

## ما ثبت من الكود

تصحيح التجهيز يغيّر بنود المستند وحركته الأصلية، مع حفظ الحالة السابقة واللاحقة في `InventorySetupChange`. بقاء القيد الافتتاحي الأصلي صحيح، لكنه لا يكفي إذا غاب قيد فرق القيمة. كذلك كانت معاينة الانتقال التاريخي تقارن القيد الأصلي بقيمة المستند الحالية فقط، فتمنع مستندًا له تصحيحات مالية صحيحة.

أصبحت `OpeningFinancialSupport::review()` تتحقق من سلسلة التغييرات، والقيد الأصلي، وقيود التصحيح والتسوية، وحركات المصدر والقيمة الحالية. تستعملها الجاهزية والانتقال التاريخي والتصحيح. تشمل المراجعة المستندات المفرغة بالكامل، ولا تعني مطابقة إجمالي الفرع وحدها سلامة أدلة كل مستند.

لم تُقرأ بيانات `goldenwomandb` أو `app_store` أثناء التنفيذ. لا يمكن الجزم بأن سجلات الإنتاج تحتوي سلسلة الأدلة المطلوبة دون المعاينة هناك بعد نشر معتمد.

## المعالجة المسموحة

| طبيعة التغيير | المعالجة |
|---|---|
| خطأ إدخال موثق وقيد فرق مفقود | فرق حساب المخزون مقابل `opening_equity`، بحسب إشارة الفرق |
| تصحيح إدخال سبق إثبات فرقه صحيحًا | إرجاع القيد الموجود دون تكراره |
| بيع حقيقي خارج التطبيق، خُصمت كميته سابقًا، وقيد فرق مفقود | مدين `cogs` ودائن `inventory`، دون حركة مخزون ثانية |
| بيع خارجي عولج سابقًا كتصحيح افتتاحي | إعادة تصنيف بين `cogs` و`opening_equity`، دون تعديل المخزون مرة ثانية |

البيع الخارجي يحتاج قيد إيراد مستقلًا ومتوازنًا لنفس الفرع مقابل قبض أو ذمم، بلا أثر مخزون أو تكلفة مكرر. لا يُنشأ بيع أو قبض افتراضي. لا يعاد تخصيص قيد الإيراد نفسه لتغيير آخر؛ الحالات المجمعة تحتاج مراجعة مستقلة. تغيير التكلفة مع خروج كمية لا يُصنف بيعًا تلقائيًا. إذا كان القبض ضمن رصيد البداية أو لا يوجد قيد إيراد مستقل، تتوقف هذه المعالجة بدل إنشاء إيراد أو قبض مكرر.

التسوية لا تعدّل المستند أو الكميات أو حركات المخزون أو القيد الأصلي أو الصندوق والبنك. تُسجل بتاريخ اليوم ضمن فترة مفتوحة، بمعرّف طلب وسبب ومرجع دليل وموافقة صريحة. القيود والتدقيق داخل Transaction واحدة مع الأقفال وإعادة التحقق وبصمة المعاينة. غياب السجل السابق أو عدم تطابقه يمنع التنفيذ، ولا يعالج بتقدير الفرق الإجمالي.

## إجراء الإنتاج بعد موافقة ونشر مستقلين

هذه خطوات للمشغّل لاحقًا؛ لم تُنفذ على الإنتاج. لا Migration جديد لهذه المعالجة.

1. أخذ نسخة احتياطية قابلة للاستعادة، والتحقق من هوية اتصال Laravel الفعلي وConfig Cache. حفظ مخرجات المعاينة في مكان خاص، بعيدًا عن `public/`.
2. اختيار المالك أو مستخدم نشط لديه `finance.transition_review` و`inventory.valuation_review` و`sales.view_cost` ونطاق الفرع الصحيح. إجراء المعاينة أولًا والميزة معطلة:

   ```text
   php artisan app:opening-corrections-reconcile --actor=USER_ID --branch=BRANCH_ID --document=DOCUMENT_ID
   ```

3. مطابقة سلسلة التغييرات مع أدلة صاحب المحل، وتحديد طبيعة كل تغيير؛ لا تُقبل تسوية بلا مستند سابق مثبت أو سلسلة تغييرات قابلة للإثبات. معاينة تغيير واحد:

   ```text
   php artisan app:opening-corrections-reconcile --actor=USER_ID --branch=BRANCH_ID --document=DOCUMENT_ID --change=CHANGE_ID --classification=entry_error --date=YYYY-MM-DD --evidence="مرجع الدليل الحقيقي"
   ```

   للـبيع الخارجي تستخدم `--classification=external_sale --revenue-journal=JOURNAL_ID` مع بقية المعطيات. كل المعرفات والمبالغ تأتي من البيانات الفعلية، وليست أرقام سيناريو الاختبار.

4. مراجعة `lines` و`delta_minor` و`status` و`other_unsettled_changes` و`revision`. القيم المالية بوحدات العملة الصغرى. لا تنفيذ عند وجود دليل ناقص أو معكوس أو تصنيف غير واضح. `no_effect` لا يحتاج قيدًا صفريًا.
5. بعد اعتماد المعالجة، تفعيل `FINANCE_LEGACY_TRANSITION_ENABLED=true` مؤقتًا وإعادة بناء Config Cache وفق إجراء النشر. هذا يفعّل أيضًا مسار الانتقال التاريخي الموجود، لذلك تحصر نافذة التفعيل بالمخوّلين.
6. إعادة المعاينة ثم تنفيذ الأمر نفسه بإضافة:

   ```text
   --execute --confirmed --reason="سبب الاعتماد الموثق" --operation=NEW_UUID --revision=PREVIEW_REVISION
   ```

   يحتفظ المشغّل بنفس UUID عند إعادة الطلب. تغير المعاينة يرفض الاعتماد؛ تلزم معاينة وموافقة جديدتان. لا معالجة جماعية تلقائية.
7. التحقق من قيد التسوية وسجل `finance.opening_reconciled` وتوازن القيود، وعدم تغير الكميات والحركات والصندوق والبنك والقيد الأصلي. إعادة تقرير الجاهزية؛ لا يتجاوز أية فروقات أخرى غير مسوّاة.
8. تعطيل العلم وإعادة بناء Config Cache. لا حذف قيود أو إعادة اعتماد افتتاح أو فتح فترة مغلقة. لا توجد في هذه الإضافة واجهة عكس آلي للتسويات؛ أي تراجع محاسبي لاحق يحتاج معالجة عكسية مراجعة، وليس حذف القيد.

## مواضع التنفيذ والاختبار

- `ReconcileOpeningCorrections::preview/execute`: المعاينة والاعتماد؛ الأمر `ReconcileOpeningCorrectionsCommand` مدخل التشغيل المقيد.
- `OpeningFinancialSupport::review/settlementLines`: الإثبات وسلسلة التصحيحات وحساب القيد.
- `LegacyFinanceTransitionAction` و`ProgressiveStockProof` و`ProgressiveOperation` و`SetupReadinessReport`: احتساب الأثر الصحيح ومنع الجاهزية عند نقصه، بما في ذلك فحص أصناف متضررة عند البيع في التشغيل الكامل.
- `CorrectInventoryAction` و`CorrectDocumentItemAction` وواجهتا التصحيح: إبقاء تصحيح الإدخال منفصلًا عن البيع الخارجي والمرتجعات.
- `InventoryController` وأزرار قائمة المخزون: تجميع قراءة الفروع المفعّل بها التشغيل التدريجي بدل استعلام لكل سطر؛ ظهر هذا الخلل في اختبار عدم نمو الاستعلامات أثناء إعادة مجموعة التصحيح.
- `OpeningReconciliationTest`: بيانات اصطناعية لقيد 600 ثم حذف 300، وتعديل التكلفة والتكرار والأدلة والإقفال والتراجع الكامل. `AuditMySqlConcurrencyTest::test_mysql_reconciliation_replays_concurrent_requests_without_duplicate_journals`: طلبان متزامنان حقيقيان على MySQL.

أدلة التشغيل المحلية في `storage/app/reports/opening-reconciliation-*.txt`. هذه اختبارات محاسبية وخدمية وCLI، وليست تجربة قبول بمتصفح أو مراجعة فعلية لبيانات الإنتاج.

النتائج الفعلية على PHP 8.5.12 / Laravel 13.35 / MySQL 8.4.3:

- الجولة الموسعة: 119 اختبارًا و1064 تحققًا، بفشل واحد في نمو استعلامات أزرار المخزون. عولج بتجميع قراءة الفروع، دون رفع سقف الاختبار.
- الإعادة النهائية للمجموعة المتأثرة، وتشمل الاختبارات الجديدة والتزامن الحقيقي: **44 اختبارًا و303 تحققات ناجحة** (`opening-reconciliation-verified-final.txt`). بقية حالات الجولة الموسعة لم تفشل، ولم تعد بلا سبب بعد إصلاح القراءة.
- واجهة الانتقال التاريخي: **4 اختبارات و54 تحققًا ناجحًا** (`opening-reconciliation-legacy-final.txt`).
- Web وFlutter/Offline والافتتاح والشراء والبيع والتراجع: **5 اختبارات و69 تحققًا ناجحًا** (`opening-reconciliation-mobile-final.txt`).
- Pint و`git diff --check` نجحا. لم تُشغّل الحزمة الكاملة لكل المشروع. لا Migration أو Seeder أو اعتماد فعلي أو نشر أو تغيير بيئة أخرى.
