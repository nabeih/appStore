# سياسة المستودع وحزمة الإنتاج

مراجعة محلية: 2026-11-21. لم يُنفذ نشر أو حذف أو تعديل لفهرس Git أو اتصال بقاعدة بيانات.

## ما يبقى في Git

- الاختبارات المصدرية في `tests/` و`phpunit.xml`، بما فيها الاختبارات الجديدة غير المتتبعة حاليًا عند مراجعتها واعتمادها لاحقًا.
- ملفات التطبيق والترحيلات وملفات القفل، والوثائق المصدرية. لا تُستبعد `docs/` كلها؛ مسار Swagger يقرأ منها `docs/openapi-flutter.yaml`.
- صور الاختبار المعتمدة كـFixtures عند الحاجة؛ ليست كل صورة ناتج اختبار.

## ما يبقى محليًا وخارج الحزمة

- Coverage وJUnit ونتائج المتصفح والكاش والملفات المؤقتة.
- `storage/app/reports/`: لا توجد ملفات متتبعة داخله حاليًا، وهو مستبعد أصلًا عبر `storage/app/.gitignore`. يحتوي أدلة تدقيق محلية ومعلومات عن قاعدة المحل، وبعض ملفات التجارب تتضمن بيانات دخول اختبارية؛ لا يُنشر أو يُرفع كما هو.
- لم يظهر في `app/` و`routes/` و`config/` استخدام تشغيلي لمسار `storage/app/reports/`. لا يشمل هذا الحكم كل الملفات أو التقارير في مسارات أخرى؛ لا حذف ولا تنظيف تلقائي لها.
- `.env` ومتغيراته المحلية، و`auth.json`، ومحتويات التخزين الخاص والعام والنسخ الاحتياطية والسجلات. الملفات العامة المرفوعة للعميل تبقى في التخزين المشترك ولا تُستبدل بملفات محلية.

`.gitignore` لا يوقف تتبع ملف سبق إدخاله. لم تظهر تقارير أو Coverage متتبعة في الفحص الحالي. إذا ظهر ملف متتبع لاحقًا، تُراجع محتوياته أولًا ثم يُقترح استبعاده من الفهرس بإجراء مستقل؛ لا تنفذ هذه السياسة ذلك تلقائيًا. تسريب سر سابق يحتاج إلغاءه/تدويره، والتجاهل وحده لا ينظف تاريخ Git.

الفحص النصي المحلي لم يجد مفاتيح خاصة أو Tokens لمزوّدين بالأنماط التي فُحصت. ظهرت كلمات مرور ثابتة في اختبارات إنشاء حسابات تجريبية، وكلمة مرور في ملف تجربة محلي غير متتبع. هذا فحص محدود، لا إثبات بأن الصور أو ملفات Binary أو تاريخ Git خالية من بيانات حساسة. تُراجع أدلة التدقيق قبل مشاركتها، ويُفضّل فحص أسرار آلي معتمد في CI لاحقًا.

## تجهيز إصدار لاحقًا، بعد الموافقة

1. لا تستخدم نسخة مجلد العمل الحالية كحزمة نشر؛ فيها تغييرات محلية وملفات غير متتبعة. راجع التغييرات واعتمد Commit كاملًا لاحقًا، دون فقد أعمال المستخدم.
2. اختبر الـCommit المعتمد على MySQL معزول، وجهّز أرشيفًا في مجلد إصدار جديد. تطبق `.gitattributes` استبعادات `export-ignore` عند استخدام `git archive`؛ تبقى `tests/` في GitHub.

   مثال تجهيز فقط، لم يُنفذ:

   ```sh
   git archive --format=tar --output=/safe/new-artifacts/appstore-release.tar APPROVED_COMMIT
   ```

   يجب أن يحتوي الـCommit المختار تعديلات `.gitattributes` نفسها وجميع الميزات المراد نشرها. لا تستخدم `HEAD` القديم أو تنشر ملفًا غير مكتمل. أمر `git archive` لا يضم الملفات غير المتتبعة أو غير المثبتة.
3. افحص قائمة الأرشيف قبل فكّه: لا `tests/` أو Coverage أو تقارير تشغيل أو `.env` فعلية أو بيانات تخزين. وجود `.env.example` وحده مقصود. لا تعتمد على `.gitignore` لاستبعادات أداة نسخ أو ZIP أخرى؛ ليست كل أدوات الحزم تحترمه.
4. في مجلد تجهيز منفصل: جهّز مجلدات Laravel القابلة للكتابة، وثبّت الاعتماديات بـ`composer install --no-dev --prefer-dist --optimize-autoloader`. لا تستخدم `composer setup`؛ يتضمن Migration. ابنِ الواجهة عبر `npm ci` و`npm run build` إن كان الإصدار يعتمد Vite، وتحقق من وجود ناتج البناء؛ `public/build` غير متتبع ولا يدخل الأرشيف تلقائيًا.
5. اربط `.env` والتخزين المشترك بالبيئة المستهدفة بإجراء مستقل. لا تنسخ التخزين المحلي أو بيانات التجارب أو كاش إعداداته، ولا تستخدم `rsync --delete` على تخزين العميل أو جذر المشروع القائم.
6. ابدأ بـTesting بعد الموافقة، وافحص الدخول والكاشير والصور وSwagger والصلاحيات والـScheduler. الترحيلات منفصلة وتحتاج موافقة؛ لا Seeders تلقائية. لا تنتقل للإنتاج حتى نجاح القبول.
7. التراجع إلى مجلد الإصدار السابق لا يشمل عكس Schema أو القيود المالية تلقائيًا. احتفظ بالتخزين والبيئة المشتركة؛ عند وجود ترحيل غير قابل للتراجع بأمان يلزم إصلاح أمامي وخطة معتمدة.

## Document Root والحماية العامة

- الإعداد الصحيح هو `/path/to/release/public`، وليس جذر المشروع. المثال المحلي في `docs/aapanel-nginx-locations.conf.example` يستخدم `public` بالفعل؛ لم يُفحص إعداد VPS الفعلي.
- Laravel يدخل عبر `public/index.php`؛ تُحفظ `app/` و`vendor/` و`tests/` و`storage/app/private/` و`.env` خارج الجذر العام.
- `public/storage` المحلي يشير إلى `storage/app/public` فقط؛ لا تربطه بـ`storage/` كله أو بمجلد التقارير/التخزين الخاص. محتوى `storage/app/public` منشور بطبيعته، فلا تضع فيه أسرارًا.
- مثال Nginx يمنع ملفات PHP الأخرى والملفات المخفية وبعض امتدادات الأسرار؛ و`public/.htaccess` يحافظ على Front Controller وتعطيل فهرسة الأدلة عند توفر الوحدات المطلوبة. لا تعالج Document Root خاطئًا بإضافة قواعد حظر فقط.
- قبل اعتماد أي نشر: تحقق من إعداد الخادم و`APP_DEBUG=false` وHTTPS وصلاحيات الكتابة، ثم جرّب من خارج جلسة الدخول `/.env` و`/.git/config` و`/composer.json` و`/tests/` و`/storage/app/private/` ومسار تقرير معروف. المقبول رفض/404 دون محتوى أو فهرسة، مع استمرار الصور العامة المسموح بها. هذا التحقق الشبكي لم يُنفذ هنا.
