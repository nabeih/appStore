# إصلاح المتجر العام وإعادة تصميمه

تاريخ التحقق: 2026-11-02. PHP 8.5.12، Laravel 13.35، Chrome فعلي، MySQL محلي.

## النتيجة والسبب الجذري

المتجر المحلي جاهز للمعاينة: http://127.0.0.1:8000/shop

كان GET /shop يرجع HTTP 503 قبل تنفيذ Blade أو JavaScript: استدعى StorefrontController إعدادات المتجر عبر settings(true)، بينما لا يوجد أصلًا سجل store_settings في app_store. ثم حوّل معالج الاستثناءات العام الخطأ إلى رسالة الطلب والحقيبة المبهمة. لم تكن المشكلة محاولة بيع أو Checkout. استثناء HttpException المتعمد مستثنى من التسجيل الافتراضي في Laravel؛ الدليل المباشر محفوظ في storefront-before-db.json، مع نوع الاستثناء وحالته ورسالة إعداد المتجر.

أصبح العرض يستخدم إعدادات احتياطية غير محفوظة، ويعرض الهيكل الكامل وحالة عدم وجود منتجات. لا ينشئ إعدادات أو ينشر منتجات تلقائيًا. إعدادات استقبال الطلبات منفصلة؛ الخادم يفحص الفرع وتفعيل المبيعات وإغلاق الإعداد ومناطق التوصيل قبل التسعير وإرسال طلب جديد. تبقى الحقيبة قابلة للاستخدام مع رسالة واضحة وتعطيل Checkout عند عدم الجاهزية، ويُرفض POST المباشر أيضًا. إعادة الطلب المقبول سابقًا بالمعرّف نفسه تحتفظ بسلوكها السابق.

عند حدوث خطأ حقيقي في صفحة عامة، يظهر قالب خطأ مفهوم دون تسريب تفاصيل تقنية. استُثني المتجر العام من Debugbar دون تغيير صفحات الإدارة.

## التصميم ومقارنته بالمرجع

فُحص https://minimoon-store.com/ في Chrome بعرض 1440 و390 بكسل، بما يشمل الرئيسية والتصنيفات وتفاصيل منتج والسلة الفارغة ومسار Checkout المتاح دون إنشاء طلب خارجي.

| العنصر | التنفيذ المحلي المستلهم من المرجع |
|---|---|
| الرأس | اسم المتجر في الوسط، تنقل يمينًا، بحث وحقيبة يسارًا، قائمة مستقلة للهاتف |
| الشريط العلوي | شريط وردي واضح بنص أصلي، دون ادعاء خصم أو شحن مجاني غير مسجل |
| المجموعات | صور كبيرة، ثلاثة أعمدة للكمبيوتر وعمودان للهاتف، مصدرها الأقسام والبنرات وصور المنتجات المنشورة |
| المنتجات | مساحات بيضاء وصور بارزة وأسعار وردية وألوان، أربعة أعمدة للكمبيوتر وعمودان للهاتف |
| التفاصيل | معرض حسب اللون، صور مصغرة، عينة قماش أو HEX، مقاسات وتوفر وكمية وإضافة للحقيبة |
| الحقيبة | نافذة جانبية، تعديل وحذف الكميات وحفظ محلي، ثم صفحة الطلب الحالية |
| التذييل | خلفية وردية داكنة، معلومات المتجر والتواصل والفرع المهيأ للنشر فقط |
| الهواتف | RTL، تحكم قابل للمس، قوائم وحقيبة مناسبة للشاشة، دون تجاوز أفقي في القياسين المختبرين |

لم يُنسخ كود المرجع أو شعاره أو صوره أو نصوصه. خط Changa مستضاف محليًا من مصدر Google Fonts الرسمي مع ترخيص SIL OFL المحفوظ بجانبه؛ لا CDN مطلوب للواجهة الجديدة. اسم الهوية ووصفها والتواصل والأقسام والبنرات والصور قابلة للإدارة بالحقول القائمة. لم تُضف حسابات زبائن أو دفع إلكتروني أو وظائف شكلية غير معتمدة. لوحة الألوان في CSS، ولم تُضف شاشة تخصيص ألوان أو حقل شعار جديد.

## الإدارة وSEO

- رابط «زيارة المتجر الإلكتروني» في قائمة إدارة الموقع يفتح مسار المتجر الحالي في تبويب جديد.
- بقيت إدارة المنتجات المنشورة والأقسام والبنرات والعروض والمناطق قائمة؛ لا بيانات وهمية في app_store.
- أصبحت تسمية إعدادات الموقع «معلومات المتجر وظهوره في Google»، مع شرح الحقول بلغة مفهومة.
- تحققت الاختبارات من Title وDescription وCanonical وOpen Graph في HTML، ومن JSON-LD صالح للمتجر والمنتج وعروض مقاساته وأسعاره وتوفرها.
- النصوص مهربة في HTML وJSON-LD لمنع حقن الوسوم. البيانات العامة لا تحتوي تكلفة أو حد بيع أدنى أو أرصدة فروع أخرى.
- /shop/sitemap.xml يعيد XML للصفحات العامة المنشورة، دون Checkout أو الإيصالات. robots.txt القائم يمنع مسارات الإدارة والطلبات الخاصة.
- الصفحة غير المهيأة والبحث والفلاتر تحمل noindex المناسب؛ صفحة الحقيبة والإيصالات noindex,nofollow. لا ادعاء بفهرسة محلية أو ضمان ترتيب Google. يجب ضبط APP_URL وHTTPS ومعلومات المتجر عند نشر مستقل.

## الإصلاحات الإضافية المحدودة

أثبت اختبار إعدادات المتجر أن StoreSetting كان يعامل id الثابت كأنه auto-increment؛ كان الكائن المنشأ يُعيد معرفًا غير صحيح وتفشل تحديثاته عبر الكائن نفسه. أُضيف incrementing=false في النموذج، دون ترحيل أو تعديل بيانات قائمة. كذلك أصبحت فلاتر اللون والمقاس تتطابق مع Variant واحد، بدل مطابقة لون من مقاس مختلف داخل المنتج نفسه.

## الاختبارات الفعلية

قاعدة المتصفح الجديدة المعزولة: appstore_storefront_20261102_tests. طبقت ترحيلاتها العادية فقط عليها، وجهزت بياناتها عبر مسارات التطبيق القائمة. تحتوي ثلاثة منتجات تجريبية و18 Variant وأقسامًا وصورًا ومناطق توصيل. الصور المستخدمة تخص المشروع، ولم تتغير ملفات الصور الأصلية. لا migrate:fresh أو حذف بيانات قائمة.

المعاينة المعبأة: http://127.0.0.1:8013/shop — خادم اختبار محلي منفصل، وليس قاعدة المحل. بيانات دخوله الاختبارية محفوظة في storage/app/private/storefront-preview/credentials.json؛ لا أسرار في هذا التقرير.

أثناء تجهيز المعزول، منع اتصال المصدر المقيد READ ONLY محاولة كتابة نتجت عن اسم اتصال منسوخ في أداة تجهيز التجربة. فُحصت الحالتان، وصُحح اسم اتصال الاختبار، ثم استُكمل تجهيز القاعدة المعزولة دون حذف أو إعادة تهيئة. المقارنة النهائية تؤكد عدم تغير بيانات أعمال المصدر.

| التحقق | النتيجة |
|---|---|
| اختبارات المتجر والتزامن والمزامنة وأمان التقارير والتثبيت | 64 اختبارًا، 711 assertions، ناجحة |
| إعادة نهائية لاختبارات الواجهة والمتجر وأمان التقارير بعد آخر التعديلات | 28 اختبارًا، 351 assertions، ناجحة |
| Chrome حي عبر HTTP، 1440 و390 بكسل | 13 لقطة، صفر أخطاء JavaScript وصفر استجابات شبكة فاشلة |
| app_store دون إعدادات ومنتجات منشورة | الرئيسية 200، Empty State كامل، Checkout معطل، لا POST أعمال |
| المتجر المعزول المعبأ | البحث والفلاتر، اللون والمقاس، تغيير الصورة، الكمية، الحقيبة واستمرارها، تسعير 95.00 وإرسال طلب وإيصال ناجحة |
| الحماية | POST لا يتجاوز الإعداد المفتوح أو غياب تفعيل المبيعات، غير المنشور 404، إخفاء التكلفة، لا نمو استعلامات بحسب عدد المنتجات |
| الجودة | Pint وnode --check وgit diff --check ناجحة |

لم تُعد الحزمة الكاملة لكل المشروع في هذه المهمة؛ شُغلت المجموعات المرتبطة أعلاه. لم يُختبر Safari أو هاتف فعلي، ولم تُختبر فهرسة Google أو بيئة الإنتاج. صور المتصفح لا تغني عن اختبارات الحفظ: الطلب التجريبي أُرسل فعليًا على المعزول فقط.

## حماية بيانات المحل وحدود التسليم

قورنت بصمات محتويات الجداول الـ74 قبل العمل وبعده. جميع بيانات الأعمال متطابقة؛ التغيير الوحيد sessions الناتج أثناء فترة التصفح. store_settings=0 وstore_orders=0 في app_store، والفترة الافتتاحية مفتوحة والمبيعات غير مفعلة. لا ترحيلات أو Seeders أو إنشاء منتجات أو إعدادات على app_store.

الفحص الحالي يختلف عن الرقم التاريخي 250.00: الكمية الإجمالية 215 وقيمة المخزون 4,650.00، ورصيد حساب inventory في الدفتر 1,500.00؛ الفرق الحسابي الحالي 3,150.00. تطابق بصمات المخزون والقيود قبل هذه المهمة وبعدها يثبت أنه لم ينشأ عن هذا التنفيذ. لم يُعالج أي فرق ولم تُنشأ قيود، ولا يعني تشغيل المتجر اعتماد جاهزية البيع.

لا Commit أو Push أو Deploy أو اتصال بالإنتاج. لا Migration جديد مطلوب لهذه التغييرات. حزمة النشر السابقة لا تتضمن هذه الواجهة الجديدة؛ تحتاج عملية تجهيز إصدار ونشر مستقلة معتمدة لاحقًا.
